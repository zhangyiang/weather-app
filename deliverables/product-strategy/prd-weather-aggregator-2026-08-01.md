## 1. 问题陈述

天气预报是城市居民最高频使用的工具型服务之一，但用户面临一个长期未被解决的核心矛盾：**没有任何单一天气平台能在所有时间、所有地点、所有天气要素上始终最准确。**

三大缺口：

| 缺口 | 现状 | 影响 |
|------|------|------|
| 准确性不可验证 | 各App自称"最准"但无从验证，8款App平均仅76.97分，38%用户因此切换App | 用户信任成本高，频繁切换无解 |
| 数据源不透明 | 墨迹融合20+源但不透明，遭遇失误后无法追溯 | 信任崩塌不可修复 |
| 多源分歧不可见 | 内容一致性仅50分，用户在矛盾中无所适从 | 决策焦虑，满意度低 |

市场规模：2025年全球23.9亿美元（CAGR 8-12.6%），中国约3830万美元（CAGR ~10%）。天气类App D1留存43.59%（全品类TOP3）、D30留存18.04%（远超全品类均值7%），验证高频刚需。

## 2. 产品目标

三个清晰、正交、可衡量的目标：

**目标一：成为准确率最可验证的天气平台**
- 聚合5+家主流气象数据源，持续比对历史预报与实际实况，动态测算并透明展示准确率
- 不声称"我们最准"，而是"帮你找到最准的那个"
- 量化：覆盖5+数据源，测算延迟≤24h，分要素分时效展示

**目标二：通过智能择优将默认预报准确率提升至行业领先水平**
- 基于动态准确率测算，自动选用当前综合准确率最高的数据源作为默认预报
- 量化：6个月内默认预报准确率超过行业TOP1 App 5个百分点以上

**目标三：以天空实拍构建"实拍即校验"的数据飞轮**
- 用户天空实拍既是社区内容，也是实况校验数据
- 量化：上线6个月内实拍UGC≥10万张，其中≥30%可用于准确率校验

## 3. 用户故事

### 核心用户画像

| 画像 | 占比 | 年龄段 | 使用频率 | 核心诉求 |
|------|------|--------|-----------|----------|
| 日常通勤决策族 | 50-55% | 25-45岁 | 日均1-3次，30秒-2分钟 | 准、快、省心 |
| 户外活动与运动爱好者 | 15-20% | 22-45岁 | 活动期日均5-10次 | 精细化+场景化指数 |
| 天气内容记录与分享者 | 10-15% | 18-35岁 | 日均2-5次 | 情感治愈+社交连接 |

### 核心用户故事

**Story 1（P0·通勤族）**：作为每天通勤的上班族，我希望打开App在3秒内看到当前天气和未来2小时降水概率，并且知道这个预报来自当前准确率最高的数据源，以便我快速决定是否带伞。

**Story 2（P0/P1·户外运动者）**：作为周末登山爱好者，我希望看到分钟级降水预报和场景化天气指数（风力/能见度/体感），并且能查看各数据源的预报分歧程度，以便做出安全决策。

**Story 3（P1·信任重建）**：作为曾被预报失误坑过的用户，我希望看到每个数据源的历史准确率记录和近期失误明细，以便理解"这次失误是哪个源的锅"，重建信任而非直接卸载。

**Story 4（P2·天空实拍者）**：作为喜欢拍天空的年轻人，我希望拍一张天空照片、标注当前实况并一键上传，这张照片既出现在社区Feed供人浏览，又自动参与准确率校验，让我获得"我的拍照帮助提升了预报准确率"的参与感。

**Story 5（P0·极端天气预警）**：作为住在极端天气频发地区的居民，我希望在暴雨/台风来临前收到及时推送，并且这条预警来自当前预警时效最准的数据源，以便有足够时间采取安全措施。

## 4. 用户研究洞察（来自瑞思）

### 六大核心痛点（按频率×影响度排序）

1. **预报不准确**（★★★★★）：38%用户首要担忧；深圳气象局评估8款App平均76.97分，实况准确性69.5分
2. **极端天气预警延迟**（★★★★★）：平均延迟9.7分钟，最长17.6分钟，涉安全
3. **不同App预报不一致**（★★★★☆）：内容一致性仅50分；超90%用户只装一款App但被"背叛"后强烈不满
4. **数据源不透明**（★★★★☆）：信息完整性仅46.3分；用户不主动关注但信任崩塌时追溯
5. **广告过多**（★★★☆）：31%用户因广告过多不满
6. **缺乏本地化实景**（★★★☆）：用户需要"此刻附近真实天空"的视觉信息

### 准确率感知特征（5个，直接决定产品设计）

1. **主观经验校准** → 需客观数据纠偏
2. **结果验证型感知** → 准确率展示需用"结果验证"语言
3. **近期记忆加权** → 需展示中长期趋势避免近因偏差
4. **一致性即准确** → 可利用一致性作为信任信号
5. **6种理解鸿沟**（天气图标误解/降水概率误解/更新频率困惑/数据源差异困惑/多设备不一致/过度精细化虚假信心）→ 需内嵌"准确率教育"

### 天空实拍/社区接受度

- 核心动机：情感治愈（零门槛放松）> 审美表达 > 社交连接 > 记忆记录 > 信息验证
- 拍照上传意愿中高（需低门槛激励）；社区浏览意愿高（浏览者:创作者≈10:1）
- 王源蓝天接龙8.2亿阅读、230万张照片，证明天气UGC有极强社交传播力
- 冷启动建议：预填充优质内容+拍摄引导+热图机制+城市维度聚合

### 关键用户需求排序（8项）

| 排序 | 需求 | 优先级 | 对应画像 |
|------|------|--------|----------|
| 1 | 高准确率默认预报（自动选最优源） | P0 | 全部 |
| 2 | 分钟级/小时级精准降水预报 | P0 | 通勤+户外 |
| 3 | 极端天气及时预警推送 | P0 | 全部 |
| 4 | 准确率透明化展示 | P1 | 全部 |
| 5 | 快速信息获取体验（3秒核心信息） | P1 | 通勤 |
| 6 | 场景化天气建议 | P2 | 户外 |
| 7 | 天空实拍记录与分享 | P2 | 分享者 |
| 8 | 多城市/多地点关注 | P3 | 通勤+户外 |

### 核心发现：全行业空白（蓝海）

**没有任何一款竞品同时具备"多数据源聚合+准确率透明展示+动态测算+自动切换最优源"四项能力。**

### 六大差异化机会

1. **准确率透明化**：从营销话术变可验证实时数据（最大蓝海）
2. **智能数据源选择**：CARROT手动切换的自动化升级
3. **准确率维度细分**：分要素分时段展示可信度
4. **实拍即校验**：天空实拍=社区内容+实况校验数据，形成数据飞轮
5. **预报分歧可视化**：诚实展示多源分歧和不确定性
6. **反广告疲劳的纯净体验**：参考Yr.no无广告模式

### SWOT要点

| 维度 | 要点 |
|------|------|
| **S 优势** | 独创准确率透明化、智能选源、UGC+准确率飞轮 |
| **W 劣势** | 数据获取成本高、冷启动挑战、品牌为零、社区冷启动、技术复杂度高 |
| **O 机会** | 38%用户痛点明确、墨迹增长停滞、AI降低多源融合门槛、付费会员市场培育 |

### 准确率关键数据

- **时效衰减**：0-12h约90% → 1-3天80%+ → 3天75-80% → 4-7天约70% → 7天+<60%（**7天是可靠性分水岭**）
- **要素难度**：温度(80-90%) > 降水有无(70-85%) > 降水量级/落区(较难) > 短时强对流(很难)
- **数据源互补**：ECMWF（全球综合第一，付费）/ GFS（免费，精度略逊）/ CMA-MESO（中国本土最优，1km分辨率，免费）/ 彩云雷达外推（短时极准，2h后衰减，付费）/ PWS众包（超本地，质量参差，免费）

- 38%用户因准确性担忧切换App（第一大流失原因）

## 8. 关键流程设计

### 8.1 准确率测算引擎流程

```
①数据采集 → 按各源频率拉取≥5源预报数据
②预报存储 → 按时间戳+要素+区域+源ID结构化存储
③实况比对 → 采集实况（气象站+PWS+UGC实拍），与同时间戳预报配对（覆盖率≥95%）
④准确率计算 → 按要素×时效×区域三维计算（7天/30天滑动窗口），延迟≤24h
⑤排行榜更新 → 更新排行榜+趋势曲线，展示延迟≤2秒
⑥自动选源 → 选用综合最高源为默认（每6h刷新）→ 首页展示推荐源预报
```

### 8.2 天空实拍上传与校验流程

```
①拍照 → 构图引导线+最佳时段提示
②标注 → 引导标注天气实况（≤3步，每步≤5秒），自动读取时间+定位
③上传 → 存储至UGC库+实况校验队列，成功率≥98%
④实况校验 → 实拍作为该时刻该地点实况数据，参与预报-实况比对
⑤准确率更新 → 该实拍参与各源该时段准确率计算
⑥社区展示 → 实拍进入社区Feed，按城市/时间排序
反馈 → 通知用户"你的实拍帮助校验了X个数据源的预报"（延迟≤24h）
```

### 8.3 用户首次体验流程

```
①打开App → 品牌Slogan展示2秒（"帮你找到最准的那个"）
②定位授权 → 授权后自动定位；拒绝则引导手动选城市（授权率目标≥70%）
③核心天气展示 → 3秒内展示实况+2h降水+7天预报+推荐源标注（首屏可见率100%）
④准确率发现 → 首次引导气泡"本预报由当前准确率最高的数据源提供"，可跳转排行榜（点击率目标≥30%）
⑤社区引导 → 首次进入社区Tab时展示"拍下你的天空，帮大家验证预报"（首次拍照转化率目标≥10%）
```

## 11. Non-goals（明确不做什么）

1. **不做自有气象模型**：聚合和择优已有源，不自建预报模型
2. **不做10天以上超长预报**：7天以上准确率<60%不可靠，尊重边界
3. **v1不做会员订阅和广告变现**：MVP聚焦核心价值验证，不引入付费墙
4. **不做社交关系链**：天空实拍社区是"内容社区"非"社交网络"
5. **不做第三方生活服务接入**：不接入外卖/出行/购物，保持纯粹性
6. **v1不做多端扩展**：桌面小组件/手表/车机为P3远期
7. **不做用户自建气象站硬件**：不涉足硬件
8. **不做AI对话式天气助手**：v1/v2不引入大模型对话，聚焦信息展示效率
